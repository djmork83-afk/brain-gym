# Архитектура BrainGym (MVP)

## Стек

**Чистые HTML/CSS/JS, ноль зависимостей и сборки.** Так сайт живёт дольше всего
и его может проверить любой человек, открыв папку: нет `node_modules`,
нет сломанных сборок через год, хостится где угодно бесплатно (Cloudflare Pages,
GitHub Pages, любой статический хостинг), легко читается и патчится.

Ограничение: ES-модули не грузятся по `file://` — нужен любой статический сервер
(`./run.sh`, `python3 -m http.server 8765`).

## Карта модулей

```
js/app.js            — hash-роутер (#/ , #/profile , #/game/<id>), экраны, шапка
js/core/i18n.js      — загрузка locales/<lang>.json, t() с плейсхолдерами {x}, смена языка
js/core/progress.js  — состояние прогресса в localStorage, XP/уровни/серия/рекорды, экспорт/импорт
js/core/ui.js        — el()/шаблоны, тосты, формат времени, шаринг
js/games/registry.js — реестр игр: id, иконка, цвет; динамический import модуля
js/games/<id>.js     — игра: start(view, ctx) → { destroy() }
```

## Контракт игры (важно для будущих игр)

```js
export default {
  id: 'math',
  start(view, ctx) {
    // view — DOM-элемент, который игра полностью заполняет своим UI
    // ctx: { t, state, finish(result), exit() }
    return { destroy() { /* снять таймеры и слушатели */ } };
  }
};

// result (передаётся в ctx.finish ровно один раз за сыгранную партию):
// { score, xp, correct, total, durationSec }
```

Правила:
- `destroy()` вызывается роутером при уходе с экрана — **обязательно чистить `setInterval`**,
  иначе таймеры продолжат жить после ухода с игры.
- Глобальные слушатели (`keydown`) навешивать в `start` и снимать в `destroy`.
- Цвета/размеры — только классы из `style.css`, чтобы темы и адаптив работали всем играм.

## Прогресс: формат и правила

Хранится в `localStorage` под ключом `bg_progress_v1` (есть поле `v` для будущих миграций):

```json
{
  "v": 1,
  "xp": 0,
  "streak": { "days": 0, "lastDay": "YYYY-MM-DD", "best": 0 },
  "best": { "math": { "score": 0, "ts": 0 } },
  "plays": { "math": 0 },
  "history": [{ "game": "math", "score": 0, "xp": 0, "ts": 0 }]
}
```

- Уровень: `floor(xp / 250) + 1` (`LEVEL_XP` в `progress.js` — единственное место смены).
- XP за партию задаёт игра (примерно 150–250 XP за хорошую партию; формулы — в файлах игр).
- Серия дней: игра сегодня → если вчера играл, +1, иначе сброс в 1.
- Экспорт/импорт — JSON-файл, импорт **заменяет** прогресс (предсказуемо; merge — в будущем).

## Локализация

- Один файл `locales/<код>.json` на язык; фолбэк — английский.
- В коде `t('game.math.title')`, плейсхолдеры `{n}`, `{score}`.
- Статические узлы шапки/футера переводятся по `data-i18n`-атрибутам.
- Добавление языка: JSON-файл + запись в `LANGS` (`i18n.js`).

## Путь к соревновательному слою (фаза 2)

1. **Честность по построению:** задания генерируются от сида (seed). Сервер знает сид,
   пересчитывает партию → лидерборд нельзя подделать, отправив «очки из головы».
   Игры уже сейчас пишутся детерминируемо от seed-friendly генераторов (RNG-хелпер),
   чтобы перейти на серверную валидацию без переписывания.
2. **Бэкенд-кандидаты** (выбрать по критерию «доступен из РФ без VPN»):
   - Cloudflare Workers + D1 — дёшево, быстро, но проверить доступность API из РФ;
   - Supabase — удобно, но зависимость от облака, который может менять политики;
   - свой VPS — максимум контроля, но больше работы (оплата сервера из РФ — отдельный квест).
3. Аккаунты лёгкие: e-mail ссылка или «ник + код восстановления», без паролей.
4. API черновик: `POST /score` (сид, ответы, время) → сервер пересчитывает → пишет в лидерборд.

## Решения-принципы (не ломать без причины)

- Никаких фреймворков и npm-сборки, пока не появится реальная необходимость.
- Никаких внешних CDN-зависимостей: сайт должен работать, когда РКН/санкции кого-то
  «отключают» — чем меньше внешних доменов, тем живучее.
- Без аналитики и трекеров по умолчанию (если понадобится — самохостящаяся, с уважением к приватности).
